# 既存データ移行計画

既存資産を本番資産として扱う。原本は変更・移動せず、権限を得た読取元から管理された複製を作り、Codex版専用の非公開取込領域へ登録する。本計画時点では実データを移動しない。

## 共通手順

1. 対象資産と所有者、保存場所、件数を読取専用で棚卸しする。
2. 元ファイルのファイル名、サイズ、更新日時、SHA-256を移行台帳に記録する。
3. 複製後のハッシュを照合し、原本同一性を確認する。
4. 元列・シート・画像位置とDB項目のマッピング表を承認する。
5. 無加工取込層へ格納し、候補値をステージングする。
6. 人が原本照合し、要確認と確認済みを分離する。
7. 件数、値、関係、履歴を照合後、承認された版だけ確定する。
8. 同一手順を再実行しても重複確定しないことを確認する。

## 対象別の方法と検証

| 対象 | 移行方法 | 検証方法 |
|---|---|---|
| 2026年6月・7月データ | シート・ファイル単位で無加工保存し、営業日単位へマッピング | 日付網羅、件数、日別値、月別集計を原本と照合 |
| 商品マスター | コード、名称、別名、価格、有効期間を版付き移行 | 全商品件数、コード重複、名称、価格、期間を照合 |
| 券売機元写真 | 画像を変換・再圧縮せず非公開Storageへ複製 | ファイル数、ハッシュ、撮影/対象日、画像可読性を確認 |
| 商品別明細 | 元の行・セル位置を保持して商品へ対応付け | 行数、商品別数量・金額、商品別合計、未対応商品を照合 |
| 時間帯別明細 | 元時間表記と集計区間を保持して移行 | 区間の欠落・重複、数量・金額、時間帯合計を照合 |
| 通帳明細 | 画像と構造化明細を分離し、摘要原文を保持 | 日付、入金、出金、残高、順序、ページ連続性を照合 |
| 修正履歴 | 可能な限り変更前後、理由、担当、日時を版として移行 | 元履歴件数、時系列、対象レコード、変更前後を照合 |
| 要確認事項 | 未解決状態のまま理由・元値・差額を移行 | 件数、状態、根拠、担当の有無を照合。勝手に解決しない |

## 売上整合性検証

営業日ごとに日別D、商品別P、時間帯別Tを独立集計し、D-P、D-T、P-Tを記録する。差額があっても移行値を変更しない。差額、対象原本、確認担当、判断結果を要確認事項として残す。

月曜日に売上実績がある場合は欠損・誤りと決めつけず、例外営業候補として原本を確認する。実績確認後は営業実績を優先する。

## 重点検証日

2026年7月8日・9日は、通常検証に加えて以下を二者確認する。

- すべての元写真と明細の対応
- D/P/Tと3差額
- 商品コード・別名対応
- 時間帯区間の境界
- 通帳明細との関係（該当する場合）
- 既存修正履歴と要確認状態
- Excel出力値との対応

## 移行判定

件数または金額が一致しない場合は移行失敗または要確認であり、自動調整して合格にしない。本移行には、移行責任者の承認、照合レポート、ロールバック手順、バックアップ復元成功が必要である。
