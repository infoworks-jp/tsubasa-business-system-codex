# Phase 0 仕様書

最終更新日: 2026-07-17

## 1. 目的

2026年6月・7月の既存資産を本番資産として移行可能にし、日別、商品別、時間帯別の売上と通帳明細を、原本および修正履歴まで追跡できるWebシステムを設計する。Mac、Windows、iPhone、Androidから利用可能とする。

## 2. 確定要件

- 正本はデータベースであり、ExcelはDBから生成する出力物である。
- 既存Excelの必要なシート構成は、調査後に将来のExcel出力仕様へ継承する。
- 移行対象は2026年6月・7月データ、商品マスター、券売機元写真、商品別明細、時間帯別明細、通帳明細、修正履歴、要確認事項である。
- 既存データはサンプルではなく本番資産として扱う。
- 原本、取込データ、確認済み値、確定値、修正履歴を追跡可能にする。
- 月曜日は当面の予定休業日とする。ただし例外営業の実績が存在する場合は実績を優先する。
- 日別売上、商品別合計、時間帯別合計の不一致を自動調整しない。各値と差額を「要確認」で保持する。
- 2026年7月8日・9日を重点検証日とする。
- Codex版とChatGPT版は比較期間中、リポジトリ、DB、保存領域、設定、処理結果を共有しない。同一の入力資料から作成した管理された複製を個別投入する。
- レスポンシブWebシステムを前提とする。
- 営業日ごとにD、P、T、3差額、状態、重点検証日、品質スコアを確認できる品質検証ダッシュボードを設ける。
- 月単位のデータ完全性、要確認件数、未確認件数、原本未登録件数、D/P/T不一致件数、通帳未照合件数を表示する。
- すべての売上データから、関連する券売機写真、通帳画像、Excel元データの登録有無を確認し、登録済み原本へ直接移動できるようにする。
- 日別売上、商品別明細、時間帯別明細、通帳明細、修正履歴から対応原本へ直接移動できるようにする。
- 原本表示では、資料種別に応じてページ番号、画像内の位置、シート名、行番号またはセル位置まで示す。
- 修正履歴タイムラインには、変更日時、変更者、対象項目、変更前、変更後、変更理由、根拠原本、確認者、承認者、状態を表示する。
- 経営者ホームに、最新営業日の売上、前営業日比、今月累計、月間目標達成率、商品ランキングTOP5、ビール販売、品質スコア、要確認件数、未照合件数、最後のバックアップ成功日時を表示する。
- 経営者ホームの各指標は、必要な確定データと定義が揃った場合だけ計算する。前年比、客単価その他の不足項目は「表示不能」または「要確認」とし、推測しない。
- 商品マスターは商品コード、商品名、カテゴリ、券売機ボタン番号、券売機表示位置、販売開始日、販売終了日、標準価格、将来利用の原価、有効状態を管理する。
- 商品カテゴリは「ラーメン」「トッピング」「ドリンク」「ご飯」「セット」「限定」を使用する。分類できない既存商品は推測せず要確認とする。
- 商品の価格変更は適用期間を持つ価格履歴として管理し、過去の価格を上書きしない。
- 券売機元写真は永久保存し、削除・上書きしない。営業日から写真一覧、商品別、時間帯別、品質確認までの処理状況を確認可能にする。
- OCRは将来機能としてフロー上に表示できるが、Version 1では実行せず、手入力経路で後続処理へ進む。
- 売上・入金照合状態は「一致」「要確認」「未照合」とし、緑・黄・赤を補助表示に使うと同時に文字でも表示する。
- ログイン成功後の最初の画面を経営者ホームとする。

## 3. 絶対に変更してはいけないルール

1. 現行つばさアプリ、既存Excel、既存データを変更、上書き、移動、削除しない。
2. 作業は `/Users/kakuyouji2/Documents/tsubasa-business-system-codex` 内に限定する。
3. 券売機元写真、通帳画像、個人情報、本番データをGitHubへ保存しない。
4. 数値を推測、補完、按分、丸め調整、他日へ付替えしない。
5. 原本ファイルを上書きしない。修正は別版として履歴化する。
6. Excelを正本として更新運用しない。
7. 未検証事項を完成扱いしない。
8. 設計レビュー承認前にアプリ実装、DB作成、サービス契約、実データ移動をしない。

## 4. 状態の定義

| 状態 | 定義 | 許可される扱い |
|---|---|---|
| 確定 | 権限を持つ担当者が原本・照合結果を確認し、承認した値または仕様 | 通常の確定集計に含める。訂正は履歴付きで行う |
| 暫定 | 出所は明確だが確認・承認が完了していない値または設計 | 確定集計と分離し、暫定表示を付ける |
| 要確認 | 不明、欠損、読取不能、重複疑い、合計不一致、意味未確定の状態 | 推測せず、元値・差額・理由を保持し、確定集計への扱いを明示する |

ゼロ、空欄、未入力、読取不能は同一視しない。状態は値とは別項目で保持する。

## 5. データ整合性

- 日別売上を `D`、商品別合計を `P`、時間帯別合計を `T` とした場合、`D-P`、`D-T`、`P-T` を個別に保存する。
- 一致判定の許容差は、決定されるまで0円と仮定せず「要確認」とする。
- 不一致の存在を理由に、いずれかの値を自動的な正として採用しない。
- 予定休業日に実績があれば、営業実績を保持し「例外営業」として示す。

## 6. セキュリティ・監査

- 原本と本番データは非公開領域に保存する。
- 利用者、権限、登録、確認、承認、訂正、出力、ダウンロードを追跡する。
- 認証情報は環境変数等で管理し、リポジトリへ含めない。
- 個人情報と口座情報は最小権限で閲覧させ、画面上では必要に応じてマスキングする。

## 7. 完成判定条件

「完成」は次の全項目が証跡付きで満たされた場合に限る。

- 承認済み仕様と受入条件がある。
- 対象機能の単体、結合、端末、権限テストが合格している。
- 2026年6月・7月の移行件数、値、原本対応、履歴が検証済みである。
- 7月8日・9日の重点検証が完了し、不一致が消去されず記録されている。
- バックアップから隔離環境への復元試験が成功している。
- Excel出力が承認されたシート・値・状態表示と一致する。
- Mac版Excelで開いた際に修復警告が表示されない。
- Windows版Excelで開いた際に修復警告が表示されない。
- Excelを保存して再読込した後も、日付、数量、金額および集計値がDB出力時と一致する。
- 既存帳票から承認されたシート構成が維持されている。
- Excel内の日付、数量、金額が文字列代用ではなく、承認された正しいデータ型で格納されている。
- ChatGPT版との比較結果が記録され、差異の理由または要確認状態が残っている。
- 重大な未解決不具合がなく、残課題が明記されている。
- 運用手順、障害対応、権限管理、バックアップ手順が承認されている。

実装済みでも未検証なら「実装済み・未検証」であり、完成ではない。

Phase 1～5に含めるVersion 1必須機能は次のとおりとする。

- 原本登録と原本位置への直接リンク
- 手入力
- 2026年6月・7月を含む既存データ移行
- 商品マスター
- 日別売上
- 商品別明細
- 時間帯別明細
- D/P/T照合と3差額の不一致管理
- 要確認管理
- 品質検証とデータ完全性メーター
- 通帳明細
- 売上入金照合
- 経営者ホームを含むダッシュボード
- Excel出力
- PDF出力
- 修正履歴タイムライン、承認、版管理
- バックアップと復元

認証、権限、監査、セキュリティは上記機能を安全に提供するための必須基盤とする。
