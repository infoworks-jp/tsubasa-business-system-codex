# 未決事項

確定済み事項は含めない。回答は `DECISIONS.md` に移し、ここから削除せず解決済み表示と決定参照を付ける。

## 開発開始前

1. **既存資産の読取許可範囲と場所**: どのフォルダ／サービスを、誰の承認で読取専用調査できるか。
2. **売上日の境界**: 深夜0時以降を暦日とするか、前営業日へ含めるか。境界時刻は何時か。
3. **業務上の売上定義**: 券売機の日別、商品別、時間帯別のうち、確定判断を誰がどの根拠で行うか。不一致時に正解を自動選択しない前提で、承認手順を定める。
4. **利用者と権限**: 利用者数、管理者・入力者・確認者・閲覧者、入力者と承認者の分離要否。
5. **クラウド制約と予算**: 海外クラウド利用可否、希望リージョン、月額上限、国内事業者必須の有無。
6. **比較の独立性**: 共通化してよいものを入力資料の複製と比較定義だけに限定するか。人による確認結果・商品対応表も相互共有しないか。
7. **個人情報の範囲**: 通帳画像等に含まれる情報分類、閲覧可能者、マスキング要件。

## 移行前

1. **既存Excelの出力継承範囲**: 必須のブック、シート名、順序、列、書式、数式、印刷設定。
2. **商品識別**: 券売機上のコード、表記揺れ、セット・トッピング・大盛り、価格変更の扱い。
3. **時間帯定義**: 元データの区間、境界、深夜帯、欠落・重複区間の扱い。
4. **通帳対象範囲**: 対象口座、対象期間、画像以外の明細有無、残高照合、売上以外の入出金を管理するか。
5. **既存修正履歴の項目**: 変更前後、理由、担当者、日時のうち何が存在し、欠損をどう要確認表示するか。
6. **不一致の許容差**: 許容差を設けるか。設ける場合も元値と実差額は保持する。
7. **移行承認者**: 試験移行、本移行、要確認解決を承認する責任者。

## 本番公開前

1. **RPO/RTO**: 許容データ損失時間と目標復旧時間。
2. **保存期間**: 原本、DB、監査ログ、出力物、バックアップの保存年数と削除承認。
3. **認証要件**: 二要素認証必須化、端末制限、セッション時間。
4. **対応環境**: サポートするOS・ブラウザの最低バージョン。
5. **障害時運用**: 通信障害時の記録方法、復旧後入力、二重登録防止手順。
6. **運用責任**: 利用者管理、要確認滞留、バックアップ、障害連絡、費用監視の担当者。
7. **公開判定者**: 受入結果と残課題を確認して本番公開を許可する責任者。
