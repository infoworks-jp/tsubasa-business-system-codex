# 給与・FL・改善推移

2026-09-20。今回のユーザー依頼に基づき `pages-rev2/` に統合。売上・商品・通帳・シフトの正本は変更しない。

## 計算とデータ

- `rev2Api('/api/fl-inputs')` が月次集計のみを返す。給与は `rev2.payroll`、長期原票売上は `historical_monthly_performance`、券売機は正規・確定の `monthly_summary`。`payroll.monthly_sales` は比較に使用しない。
- 支給計は交通費を含む控除前。会社負担を含む人件費と分離。社会保険は `social_insurance_reconciliation` の月次控除・確認条件と実際の通帳行を照合し、納付総額−従業員控除で計算。給与のみ／給与＋社会保険差引額（調整前）／会社負担全額を含む総人件費の3範囲を分離する。総人件費は返金・労働保険等の配分未確定のためNULL。
- 正規・確定の請求書由来の食材・飲料仕入だけを「登録済み部分」に集計。同じsource_keyは重複計上せず、通帳支払は加算しない。現状は月全体の網羅性と棚卸が確認できず、F・FLはNULL。将来の確定は専用の原価・会社負担の証拠を整備し、モデル・API・テストを併せて変更する。
- 累計率は費用合計÷同系列の売上合計。1か月でも欠損があれば率を確定しない。グラフは欠損を接続しない。並べ替えは両方向ともNULLを末尾。
- 給与率変化の分解は、給与変化を開始月売上で評価した後、終了月売上へ変更する順序。施策の因果効果ではない。
- 8月は依頼者の修正版原票と明細を照合し、既存行を訂正。確認履歴は匿名で表示。個人名・個別支給額・原票・DB退避はGit管理しない。変更前後・原票ハッシュの照合記録は作業環境の非公開監査記録へ保存。

## UIと検証

既存人件費タブを「FL・改善推移」に変更。みんなのトップのサマリーから全給与月へ遷移。上部の月選択は給与月も含む。FLの期間は独立して明示し、上部の月変更時は単月へ同期。トップは選択月・累計に同期する。遅れて完了したトップの取得は別タブを上書きしない。

- `node --test tests/fl-model.test.cjs`：合成データで欠損、重複、系列、累計、分解、ソートを検証。
- `pnpm exec playwright test --config=playwright.fl.config.ts`：PC・スマホでDB照合、操作、既存画面を検証。`FL_URL`で公開URLを指定可能。
- 既存 `pages-rev2.spec.ts` の給与テストは6月の差引額・翌月納付、7〜8月の未照合表示を確認。

原価と会社負担の未確定は実績データ上の制約。UIの実装完了と原価確定を混同しない。

原価資料の調査：ローカルの仕入経費整理修正版Excel、DB documents/expenses/monthly_operating_costs/bank_transactions、既存procurement-detail画面を確認。既存画面には他食材と酒類の片頁欠落の記録もある。月次全量・棚卸は確認できない。Library本体の読取ツールはこの環境にはない。

同時更新の統合：先行して公開されたfl-trends.jsの旧モデルと回帰試験は保持し、ブラウザ描画はfl-dashboard.jsに一本化。旧flTrendsタブ名・#fl・openTsubasaFLは新しい画面へ接続。再取得ボタンも維持。複数showTabラッパーの重ね掛けを防止。
