# アーキテクチャ比較案

基準日: 2026-07-17。金額は構成比較用の公開価格概算で、開発人件費、税、為替、独自ドメイン、超過従量料金を含まない。契約前に再見積する。

## 共通方針

- TypeScriptベースのレスポンシブWeb UIを有力候補とするが、Next.js採用は未決定。
- DBを正本とし、原本ファイルは非公開オブジェクトストレージへ保存する。
- PostgreSQLを第一候補とする。標準SQL、バックアップ、移行性を重視するためである。
- 原本のハッシュ、取込履歴、変更履歴をDBで管理する。
- GitHubにはソースと匿名化されたテスト用固定データだけを置く。本番資産は置かない。

## 案A: Vercel + Supabase（フルマネージド）

構成: Next.js/Vercel、PostgreSQL・認証・Private Storage/Supabase。

| 評価軸 | 内容 |
|---|---|
| 初期費用 | サービス初期費用は原則0米ドル。ドメイン等は別 |
| 月額概算 | 本番はVercel Pro 20米ドル＋Supabase Pro 25米ドル＝45米ドルから |
| 保守性 | 高い。OS、DB基盤、TLS、配信基盤の運用負担が小さい |
| スマホ対応 | レスポンシブUI/PWAを実装可能 |
| Mac開発 | Node.js、Docker任意で容易 |
| バックアップ | Supabase Proの日次DBバックアップに加え、原本の別系統コピーを設計する |
| 移行性 | PostgreSQLと標準ファイルを使えば比較的高い。認証・Storage APIは置換が必要 |
| 注意点 | 2社依存、為替、無料枠は本番不向き、リージョンと個人情報取扱いの確認が必要 |

公開価格参照: [Vercel Pricing](https://vercel.com/pricing)、[Supabase Pricing](https://supabase.com/pricing)。

## 案B: 単一VPS + Docker（低月額・自己管理）

構成: 1台の国内または近隣リージョンVPS上にWebアプリ、PostgreSQL、リバースプロキシをDockerで配置。原本はS3互換の別ストレージへ暗号化保存する。

| 評価軸 | 内容 |
|---|---|
| 初期費用 | サービス初期費用は0～数千円程度が一般的。構築・運用作業は案Aより多い |
| 月額概算 | VPS・ストレージ・外部バックアップ合計で概ね2,000～6,000円を想定。事業者確定後に再見積 |
| 保守性 | 中～低。OS更新、DB更新、監視、証明書、障害復旧を管理者が担当 |
| スマホ対応 | アプリ実装は案Aと同等 |
| Mac開発 | Docker Desktop等で本番に近い開発が可能。初期設定は多い |
| バックアップ | DBダンプ＋ボリューム／原本の別事業者または別リージョン保管が必要 |
| 移行性 | 高い。Docker、PostgreSQL、S3互換を守れば移設しやすい |
| 注意点 | 単一障害点、セキュリティパッチ、復元訓練、担当者不在リスク |

月額は候補事業者・容量・バックアップ世代数未確定のため概算であり、契約価格ではない。

## 案C: Cloudflareサーバーレス（最小固定費候補）

構成: Pages/Workers、D1、R2、Accessまたは別認証。フレームワークはWorkers互換構成を選ぶ。

| 評価軸 | 内容 |
|---|---|
| 初期費用 | 原則0米ドルから検証可能 |
| 月額概算 | 小規模なら0～15米ドル程度を候補レンジとするが、利用量と採用機能で要再計算 |
| 保守性 | インフラ運用は軽いが、Cloudflare固有仕様への理解が必要 |
| スマホ対応 | レスポンシブUIを実装可能 |
| Mac開発 | CLIで可能。ローカルと本番の差の検証が必要 |
| バックアップ | D1エクスポートとR2の別系統コピーを独自運用する |
| 移行性 | 中～低。D1はSQLite系で、PostgreSQLへの移行・機能差対応が必要 |
| 注意点 | 複雑な集計、監査、DB制約、移行ツールを技術検証する必要がある |

## 比較結論と推奨案

Phase 1の技術検証対象として案Aを暫定推奨する。理由は、本番資産の保全、監査、DBバックアップ、少人数保守を優先した場合、月額差より運用事故リスクの低減が大きいと見込むためである。ただし採用確定ではない。

費用最優先なら案Bも有力である。案Aと案Bについて、代表的な匿名化データで「復元時間」「原本100GB時の費用」「管理者の月間保守時間」「サービス移行手順」を比較してから決定する。案Cは低固定費だが、監査性と複雑な照合に対するDB適合性を実証できた場合のみ本番候補に残す。

## バックアップ共通要件

- DBと原本を別々にバックアップする。
- 本番と同じ認証情報だけに依存しない別系統保管を設ける。
- 暗号化、保持期間、世代数、削除権限を定義する。
- バックアップの存在確認ではなく、隔離環境への復元成功を合格条件とする。
- Codex版とChatGPT版のバックアップも共有しない。
